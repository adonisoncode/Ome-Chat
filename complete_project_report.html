Abstract

In an era dominated by persistent digital footprints and complex authentication barriers, there is a growing need for lightweight, friction-free communication platforms that prioritize user privacy and data ephemerality. This project, Ome-Chat, presents a modern Single Page Application (SPA) designed to facilitate real-time, anonymous messaging with a unique automatic data expiration mechanism.

The primary objective of this project is to develop a serverless chat application that eliminates the traditional barriers to entry found in mainstream messaging platforms. Unlike conventional apps that require lengthy sign-up processes and permanent data storage, Ome-Chat leverages Firebase Anonymous Authentication to allow users to join the network instantly without providing personal credentials. This "click-and-chat" philosophy is supported by a robust back-end infrastructure built on Google Firebase Cloud Firestore, ensuring millisecond-latency message synchronization across all connected clients.

A core distinguishing feature of Ome-Chat is its implementation of Ephemeral Messaging. To ensure the platform remains lightweight and to uphold a philosophy of digital impermanence, the application includes a client-side automated cleanup protocol. Upon initialization, the system automatically queries the database for messages older than one hour and purges them. This mechanism serves two purposes: it reduces database storage costs and maintenance overhead, and it provides users with a sense of temporal privacy, akin to casual, unrecorded spoken conversations.

Technically, the project adopts a minimalist "Single-File" architecture. By utilizing Babel Standalone for runtime JSX compilation and Tailwind CSS via CDN for styling, the entire application logic, user interface, and database configuration are encapsulated within a single HTML file. This architectural choice demonstrates the power of modern browser capabilities and simplifies deployment to static hosting behaviors like GitHub Pages. The User Interface (UI) deviates from the standard "corporate flat design," instead embracing a Cyberpunk/Sci-Fi aesthetic.

In summary, Ome-Chat successfully demonstrates how modern web technologies can be orchestrated to build a fully functional, aesthetically distinct, and privacy-conscious communication tool with minimal infrastructure code.

Chapter 1: Introduction

1.1 Introduction to Project

The Ome-Chat application is a real-time web-based communication platform designed to provide instant connectivity between users without the burden of complex registration processes. In the modern digital landscape, communication tools are ubiquitous, yet many suffer from "feature bloat" and invasive data retention policies. Ome-Chat addresses these issues by offering a stripped-down, focused messaging experience that runs entirely in the browser.

Built using React.js for the frontend and Firebase for the backend, the project exemplifies the "Serverless" architecture paradigm. This approach removes the need for managing physical servers, allowing the application to scale automatically based on user demand.

1.2 Project Category

This project falls under the category of Web Application Development and Cloud Computing. Specifically, it can be classified as a Real-Time Communication System utilizing a Serverless Backend-as-a-Service (BaaS) model.

1.3 Motivation

The motivation behind Ome-Chat stems from the observation that modern chat applications are increasingly heavy and data-hungry. Users often want to have quick, temporary conversations without their data being stored indefinitely on corporate servers. Furthermore, for developers, there is a need to understand how to build complex interactive systems with minimal overhead. Ome-Chat serves as a proof-of-concept for high-performance, low-latency applications built with a minimal codebase.

1.4 Problem Definition

Traditional chat applications require:

  • lengthy sign-up forms (email, phone number verification).
  • Installation of heavy native applications.
  • Permanent storage of chat history, which raises privacy concerns.
  • Complex server setup and maintenance costs.
Ome-Chat aims to solve these problems by providing an instant-access, web-based, anonymous, and self-cleaning chat environment.

1.5 Goals and Objectives

Goals:

  • To create a functionally complete chat application in a single file.
  • To ensure real-time data synchronization with sub-second latency.
  • To implement privacy-enhancing features like auto-deletion of messages.

Objectives:

  • Implement Firebase Anonymous Auth for seamless login.
  • Design a Cyberpunk-inspired UI using Tailwind CSS.
  • Develop a message expiry system that deletes data older than 1 hour.

1.6 Scope and Applications

The scope of this project is limited to text-based communication. Future scopes could include file sharing or voice calls.
Applications:

  • Internal team coordination tools.
  • Temporary support chat for websites.
  • Anonymous feedback systems.
  • Educational tool for learning React and Firebase.

Chapter 2: Literature Review

Real-time communication on the web has evolved significantly over the last two NOT decades. Early systems relied on HTTP Polling, where the client would repeatedly ask the server for new data. This was inefficient and caused high server load.

Historical Context

With the advent of AJAX (Asynchronous JavaScript and XML) in the mid-2000s, the web became more dynamic. However, true real-time bidirectional communication was only unlocked with the standardization of WebSockets in 2011 (RFC 6455). WebSockets allowing for a persistent connection between client and server.

Existing Systems

WhatsApp and Telegram are the market leaders.

  • WhatsApp: Uses the Signal protocol for E2E encryption but requires phone numbers and stores metadata.
  • Telegram: Offers cloud sync but default chats are not E2E encrypted. Both are heavy applications.
Ome-Chat differs by targeting the "ephemeral" niche—interactions that are not meant to be saved.

Chapter 5: Methodology

The development methodology followed was Agile. The project was built in iterative sprints.

  1. Sprint 1: setup of HTML shell and Tailwind CSS.
  2. Sprint 2: Integration of React via Babel Standalone.
  3. Sprint 3: Authentication Implementation (Firebase Anon Auth).
  4. Sprint 4: Chat logic (Send/Receive) using Firestore `onSnapshot`.
  5. Sprint 5: UI Polish (Cyberpunk theme) and Message Expiry Logic.

Algorithm: Message Auto-Deletion

    Step 1: On Component Mount:
    Step 2: Calculate TIMESTAMP = CURRENT_TIME - 1 HOUR
    Step 3: QUERY database for documents where createdAt < TIMESTAMP
    Step 4: IF documents found:
        Step 5: Execute BATCH DELETE
        Step 6: Log "Cleanup Complete"
    Step 7: ELSE: Do nothing.

Chapter 6: Implementation, Testing, and Maintenance

6.1 Description of Frontend Code

The frontend is built using React functional components. The main `App` component manages the authentication state. If the user is unauthenticated, it renders the `LoginScreen`; otherwise, it renders the `ChatRoom`.

Key Components:

  • App(): Root entry point.
  • LoginScreen(): Static view with animation and "Connecting..." visuals.
  • ChatRoom(): Handles the message list, input form, and realtime listeners.

6.2 Description of Admin Code (Backend Security)

While there is no dedicated Admin UI, the backend security is enforced via Firestore Security Rules.
Example Rule: 

    match /artifacts/{document=**} {
      allow read, write: if request.auth != null;
    }
This ensures only authenticated (anonymous) users can read or write messages.

6.3 Testing Techniques

Unit Testing: Individual functions like the cleanup logic were tested with mock dates.

Integration Testing: Verified that sending a message on Client A appears immediately on Client B.

Performance Testing: Lighthouse audits were run. The app achieves a 95+ score due to the lightweight nature of the code (no heavy bundlers needed for production in this specific setup).

Chapter 8: Conclusion & Future Work

8.1 Conclusion

The Ome-Chat project successfully demonstrates the capability of modern web technologies to create powerful, engaging applications with minimal code. By leveraging the "Single-File" paradigm, we proved that complex build tools are not strictly necessary for all React applications. The integration of Firebase provided a seamless backend experience, allowing for true real-time functionality without determining server management.

The system meets all primary objectives: instant access, privacy through ephemerality, and a responsive, aesthetic user interface.

8.2 Limitations

  • Security: Anonymous auth provides no way to recover accounts if browser data is cleared.
  • Scalability: The single-file structure becomes hard to maintain if the code exceeds 1000 lines.
  • Media: Currently limited to text; no image or video support.

8.3 Future Enhancement

  • Media Support: Integrate Firebase Storage for image uploads.
  • Private Rooms: Allow users to create password-protected channels.
  • PWA Support: Convert the app into a Progressive Web App for offline capabilities.
